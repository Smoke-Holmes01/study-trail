# 双端 v0.0.1 实施与验证记录

日期：2026-10-21。业务基线为需求分析和系统设计v0.0.1；本记录描述本轮实际源码、迁移及运行检查，旧日期记录保留其原适用范围。

## 实施结果

- 新增独立管理端登录、会话/CSRF、11项导航业务页及配置表单，延续用户端视觉变量与双主题。
- 实际合同为85个不重复operation ID：59项既有用户操作、RT-01运行限制读取、25项管理操作。用户端/api/v1与管理端/api/admin分别认证。
- 数据库从19表增量扩展至29表；追加冻结0005迁移，原0001—0004未重写。
- 数据库成为平台模型、八类流程提示词、Skills、MCP与限制的唯一运行来源；文件仅初始化导入。修订、凭据版本和引用保持不可变。
- 新任务固定生成/嵌入/重排、提示词、工具、技能和限制；凭据只以版本引用进入快照。后台留空保留原凭据；主密钥位于部署环境。
- 用户停用撤销全部会话与SSE接收，已受理任务继续执行保存。管理员不能通过管理接口访问私有学习正文、文件名、图片或完整快照。
- 资源创建、任务运行、每次真实调用尝试及管理操作分别采集；删除私有资源不删除历史事实。区分未采集、部分覆盖、真实零值和加载失败。
- 修复过时的浏览器五标签步骤、接口模拟及隔离环境Origin；用户上传提示读取后台公开限制，提交前刷新并由服务端再次检查。
- 数据库事务在发送成功响应前提交，避免页面立即重读到旧状态或在提交失败后仍看到成功。

## 真实联调

使用新建专用普通账户、合成矩阵/向量问题与短文本资料，没有发送原有用户的私有学习内容。

生成、文件嵌入发布、RAG查询与重排、结构化计划保存、提示词生成、MCP发现及实际工具调用均成功。实际尝试为生成10、嵌入3、重排2、MCP工具1，共16次；未发生自动循环重试。

脚本 `backend/tools/verify_live.py` 使用共享预算计数，达到30次即拒绝后续调用；结果文件存在时拒绝重复运行。MCP工具发现不是call_tool，不虚增工具执行次数。

[真实结果JSON](verification-live-v0.0.1.json)只保存场景、任务标识、安全错误、状态与计数，不含提供商响应正文和凭据。测试运行使用本机既有连接配置；连接成功不证明答案正确性或全部图片、上下文能力兼容。

真实联调开始前，自动审批首次要求明确外发内容及目标地址。完成只读目标核对并确认仅使用合成数据后，第二次审批通过；无剩余审批阻塞。

## 本机迁移、备份与恢复

已实施0004→0005，29表，初始化独立管理员study_admin。原有普通账户、智能体、对话、计划、知识库、消息、来源与其他原业务表按原字段/主键排序计算哈希；新管理字段和统一撤销的会话不纳入旧字段比较。迁移后哈希与升级前一致。

私有存储17份文件逐份SHA-256与备份一致。真实联调随后创建的专用账户与合成资料是新增数据，不属于原数据校验对象。

最终备份：`src/.local/backups/platform-20261021-final/`。

- `database.dump`：升级前PostgreSQL自定义格式备份；已实际恢复到独立库。
- `storage/`：同一维护窗口复制并逐份校验的私有文件。
- `backend.env`：升级前本机环境；`backend-upgraded.env`：初始化加密密钥后的环境。两者均是本机秘密文件，不纳入源码发布。
- `rehearsal.json`：独立恢复、重复导入、原数据哈希及存储核对结果；`applied.json`：本机应用结果。
- `rehearsal-key.json`：仅供隔离演练副本解密的密钥，不是日常库主密钥。

演练曾发现索引指纹回填触发updated_at自动更新，已修复为保留旧时间，并从原dump重新恢复新副本通过。随后重复演练暴露演练工具重新生成临时密钥的问题，已改为首次导入前持久保存并复用。日常库使用独立密钥，升级后解密与重复初始化检查通过。

本机启动脚本只读检查安装状态，不自动应用迁移。首次新环境可显式运行alembic及bootstrap；已有环境升级应使用先演练、后备份核验、再apply_upgrade的流程。

恢复步骤：

1. 暂停新任务并停止记录的API/worker/前端进程；保留当前数据库及文件作故障诊断备份。
2. 将选定database.dump恢复到一个新的独立数据库，使用其匹配的私有文件副本、密钥环和源码版本验证可读，不直接覆盖唯一现存数据库。
3. 核对账户、学习对象、来源及文件哈希，确认模型配置和凭据可解密后，再明确切换DATABASE_URL与STORAGE_ROOT并启动。
4. 若恢复升级前0004库，必须使用匹配的旧源码和升级前环境；当前v0.0.1启动检查会拒绝未升级的库。旧源码历史备份另位于项目同级20261020的Git备份目录，恢复前需核对清单。

禁止用删除新增表或替换密钥的方式冒充无损回退。0005的downgrade明确拒绝破坏性操作。正式环境或Linux恢复没有在本轮执行。

## 未验证与适用边界

本轮未逐一进行全部模型、真实多图、提示词润色、项目指南回答内容、外部限流/断网组合及完整学习质量实验。Linux完整启动、性能容量指标和论文实验未执行。对应功能的源码/技术测试与真实联调状态在追踪表中分别列明。

没有增加知识结论自动复核、自动修订、教师审核、掌握度统计或计划完成打卡。结构化计划校验及一次格式修复属于保存技术检查。界面和原型完成不等于软件验收，单次软件运行成功也不代表全领域回答正确。
