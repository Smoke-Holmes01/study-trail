# 空配置初始化变更与验证

本文件保留各修复阶段的过程与验证边界，阶段中的“尚未推送”描述属于当时状态；最终发布结论以[0.0.3验证记录](验证记录-v0.0.3.md)为准。
日期：2026-10-21。此记录对应0.0.2发布后的工作区调整；不改写已发布tag或原发布验证证据。

## 当前规则

全新初始化只创建管理员、八个流程提示词、四项内置技能和运行限制，不创建生成、嵌入、重排模型、MCP服务及模型用途绑定。模型JSON和MCP JSON仅保留为旧格式与隔离测试样例，普通初始化不读取它们，也不解析其中的外部服务凭据。已有库的模型、MCP、凭据和管理员编辑保留。

空模型目录返回200和`default_model_id:null`；运行限制接口额外返回三类模型用途绑定的启用状态，不表示实际连接测试通过。平台可正常启动、登录和配置。缺少默认生成模型时创建智能体返回409 REQUIRED_CONFIG_MISSING；管理员新增后首次绑定传`expected_version:0`，有绑定时必须传当前版本，过时版本返回409。只有生成模型即可创建智能体和受理普通答疑，嵌入与重排快照允许为空；知识库索引需要嵌入模型，未配置时上传被拒绝。只配置嵌入模型也可受理文件索引，不强制要求生成模型。

学生端提供配置提示并在缺少嵌入模型时禁用上传；管理端提供添加模型、用途绑定及MCP引导。后台保存仍执行最终验证。普通初始化不覆盖已有内容；旧指南升级仍使用显式`--refresh-guide`，保留历史修订。

## 验证结果

- 隔离后端完整回归：80项通过，包含3项新增场景：空目录与重复初始化、管理员首次绑定及冲突保护/仅生成模型答疑、仅嵌入模型文件处理。空模型环境的安装检查通过。
- 前端单元回归：29项通过；OpenAPI与前端类型重新生成，类型检查和生产构建通过。
- 双端浏览器：原9项通过；新增空配置引导场景首次因提示框包含关闭按钮而未命中精确文本，改为状态区域定位后单独复跑通过，共10项覆盖。
- 接口保持85项、67条路径；业务表保持29张，迁移仍为0006；135条功能需求和49项验收编号保留。

测试只使用study_trail_test、study_trail_e2e和模拟提供商，新增测试数据由受数据库名称限制的专用测试工具显式配置。没有调用真实付费模型或外部MCP，没有重置或清理当前业务库。因此当前已初始化库仍可能显示原来的四个模型。

本轮未发布远程代码、未移动0.0.2标签。此前完整迁移、备份恢复和真实调用边界仍以[原0.0.2验证记录](验证记录-v0.0.2.md)为准，本次不重复声称验证这些项目。
